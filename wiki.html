第一次開機，誰能聽見這台 PC？

PC 按下 DHCP，伺服器卻在另一個網段。第一個封包停在哪裡？

尚未取得位址的 PC 會在自己的區域網路廣播 DHCPDISCOVER。路由器把兩側分成不同的廣播範圍，另一側的伺服器需要中繼協助。

PC-A用戶端 LAN192.168.10.0/24
R-GW接 PC 的 G0/0192.168.10.254/24
R-DHCP遠端 DHCP 伺服器10.0.0.2/30

教學拓樸：R-GW 的 G0/1（10.0.0.1/30）與 R-DHCP 的 G0/0（10.0.0.2/30）直接相連。本文所有位址均為這組示例。

先把同一網段想成一次本地廣播能抵達的範圍。若用戶端和伺服器在同一 LAN，伺服器可直接聽見要求；本例隔了一台路由器。

一筆新租約的四封訊息

怎麼分辨伺服器提出一個位址，和用戶端真的拿到租約？

首次成功租用新位址的典型順序是 Discover、Offer、Request、ACK，簡稱 DORA。

D · DiscoverPC 在本地詢問「哪一台伺服器能提供設定？」
O · Offer伺服器提出可提供的位址和參數。
R · RequestPC 表明選擇哪個提議，請求使用該位址。
A · ACK被選中的伺服器確認租約和設定。

只觀察到 Offer 時，還要繼續追 Request 與 ACK。續租流程可能省略前面的步驟。

中繼負責傳遞訊息；提出位址及確認租約的是 DHCP 伺服器。觀察 DORA 時請先辨認訊息種類，再看每一段由誰轉送。

追蹤要求與回覆的路徑

遠端伺服器怎麼知道 PC 位於 192.168.10.0/24？

R-GW 收到 PC 的初始廣播，將接收介面的 IP 填入 giaddr（中繼位址），再把要求單播給指定的伺服器。

① PC-A → R-GWPC 廣播 Discover，初始 giaddr 為 0.0.0.0。
② R-GW → R-DHCP本例 giaddr 填 192.168.10.254，單播目的地是 10.0.0.2。
③ R-DHCP → R-GW伺服器據 giaddr 選用戶端網段的位址池，將回覆送往 192.168.10.254。
④ R-GW → PC-A中繼在用戶端 LAN 交付回覆；本地送達方式取決於廣播旗標等條件。

想查為什麼沒有收到 Offer，要同時確認伺服器能選到正確的池，也能把回覆送回 giaddr。

這是單一中繼、未啟用額外選池政策的例子。R-GW 對伺服器送出的介面是 G0/1，填進 giaddr 的卻是收到用戶端廣播的 G0/0 位址。

把 helper 放在收到廣播的一側

哪台設備、哪個介面要輸入 ip helper-address？

在 R-GW 連接 PC-A 的 G0/0 設定 helper，參數填遠端伺服器 10.0.0.2。以下指令從 R-GW 的全域設定模式開始。

interface GigabitEthernet0/0
 ip address 192.168.10.254 255.255.255.0
 ip helper-address 10.0.0.2
 no shutdown
exit
interface GigabitEthernet0/1
 ip address 10.0.0.1 255.255.255.252
 no shutdown
end

設定後查看 R-GW 的 running-config，確認 helper 位於 G0/0 下；在本例 G0/1 是傳往伺服器的一側。

先進入 enable、configure terminal，再輸入本例設定。不同機型的介面名稱可能不同，實際操作以連接 PC 所在 LAN 的三層介面為準。

把用戶端網段寫進位址池

伺服器連在 10.0.0.0/30，為什麼池要寫 192.168.10.0/24？

池描述 PC 要取得的網路設定。R-DHCP 在本例提供 /24 遮罩及 PC 所在 LAN 的預設閘道。以下從 R-DHCP 全域設定模式開始。

interface GigabitEthernet0/0
 ip address 10.0.0.2 255.255.255.252
 no shutdown
exit
ip dhcp excluded-address 192.168.10.1 192.168.10.20
ip dhcp excluded-address 192.168.10.254
ip dhcp pool CLIENT-LAN
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.254
end

本例動態位址範圍為 .21～.253。192.168.10.21 是可能的租約；實際值要看伺服器紀錄。

Option 1 是子網路遮罩，Option 3 是給 PC 的路由器位址。本例 default-router 和 giaddr 都是 .254，但用途分別是 PC 對外轉送和伺服器辨識中繼。

去程到了，回覆往哪裡走？

R-GW 可以 ping 到 10.0.0.2，為什麼還要看 R-DHCP 的路由表？

兩台路由器在 10.0.0.0/30 上直接相連，但回覆的目的地是 giaddr 192.168.10.254。R-DHCP 還需要一條能到該位址的有效路由。

先查目的地在 R-DHCP 的特權模式輸入 show ip route，檢查到 192.168.10.254 的路徑。
補上回程本例假設沒有其他可用路由。下一跳是相鄰的 R-GW：10.0.0.1。
R-DHCP# configure terminal
R-DHCP(config)# ip route 192.168.10.0 255.255.255.0 10.0.0.1
R-DHCP(config)# end
R-DHCP# show ip route

若已有能正確送達 giaddr 的動態路由或預設路由，就沿用原路徑。

Cisco 的 ip route 使用目的網路、遮罩及下一跳。例中 10.0.0.1 是伺服器路由器的鄰居；192.168.10.254 是用戶端側介面，也是本次回覆要找的中繼位址。

怎樣才算 PC 真的拿到正確設定？

做完設定後，哪兩端的資料可以互相核對？

讓 PC 重新選擇 DHCP，先讀它實際拿到的 IP、遮罩和閘道，再到 R-DHCP 對照 IP 與租約。

PC-APacket Tracer → Desktop → IP Configuration → DHCP。此例應取得 192.168.10.21～253 其中一個位址、遮罩 255.255.255.0、閘道 192.168.10.254。
R-DHCPshow ip dhcp binding：找 PC 剛取得的 IP 與對應用戶端；show ip dhcp pool：看位址池資訊。
PC-A再 ping 192.168.10.254 檢查 PC 到閘道的連通性。單一次 ping 只能驗證該段連線。

以上是操作步驟與預期值。實際租約、封包與 ping 結果應從自己的實驗讀取。

故障定位時，觀察到伺服器已有租約與 PC 已正確套用設定，是兩項不同的證據；把它們放在一起才有助於縮小問題範圍。

依最後看見的封包找下一步

同一個「DHCP 失敗」，可能卡在哪個環節？

依目前掌握的證據，先查最靠近封包停止位置的設定。

只有本地 Discover查 R-GW 的用戶端側介面及 helper 目標，再查到伺服器的路徑。
伺服器收到要求，未見 Offer看 giaddr、相符的 network、池內是否仍有可分配的位址。
伺服器送出 Offer，PC 收不到查伺服器到 giaddr 的回程；若 Offer 已到中繼，再看中繼到 PC 的 LAN。
有 IP，但跨網段不通比對 Option 3、PC 的閘道與實際介面，接著逐段檢查路由。

每一列都是下一個要驗證的假設；要靠設定或封包結果決定實際原因。

在 Packet Tracer 的 Simulation 模式下可逐段觀察。本表把前面各條目的機制串起來，適用於本教學的雙路由器拓樸。

你能從三個位址找出錯誤嗎？

同學把 helper 填成 192.168.10.254，又把池裡的 default-router 填成 10.0.0.2。該怎麼改？

先對照各欄位的使用者：中繼要找伺服器，PC 要找本地閘道，而伺服器要找通往中繼的下一跳。

① helper 應填哪個 IP？設在哪裡？

在 R-GW 的 G0/0 設定 ip helper-address 10.0.0.2，讓接收廣播的介面將要求轉給 R-DHCP。

② 位址池應發給 PC 哪個閘道？

default-router 192.168.10.254。這個位址位在 PC 所在的 LAN。

③ R-DHCP 到用戶端網段經過哪個鄰居？

經 10.0.0.1，也就是對端 R-GW 的 G0/1。回覆要到的 giaddr 是 192.168.10.254。

能說明這三個位址各由哪台設備使用，就可以把這套判斷方法移到其他用戶端網段。

S1 · RFC Editor

RFC 2131 · Dynamic Host Configuration Protocol

閱讀位置　§3.1；§4.1

用戶端初次租址時在本地廣播 Discover，伺服器提出 Offer，用戶端以 Request 選擇，伺服器用 ACK 確認。giaddr 非零時，伺服器把回應送往該中繼位址。

四步流程限首次取得新租約，其他 DHCP 狀態有不同交換。

RFC 1542 · Clarifications and Extensions for BOOTP

閱讀位置　§4.1.1；§4.1.2

中繼收到 giaddr 為零的要求時，以收到要求之介面的 IP 填入該欄位。回覆抵達後，依用戶端狀態及廣播旗標等條件在本地遞送。

DHCP 沿用 BOOTP 中繼行為。本例只有一台中繼。

RFC 2132 · DHCP Options and BOOTP Vendor Extensions

閱讀位置　§3.3 Subnet Mask；§3.5 Router Option

Option 1 提供用戶端子網路遮罩；Option 3 列出用戶端所在子網的路由器位址。

Option 3 是交給用戶端的參數。giaddr 是中繼寫入的標頭欄位。
